## Decisões Tomadas

- **Duas fontes de dados para as capturas, de propósito:** dev server (perfil de exemplo da fixture)
  para Estimativa, Detalhamento e Insumos; build de produção (armazenamento vazio) para o Onboarding.
  Forçar tudo numa fonte só produziria ou um onboarding falso ou telas vazias.
- **Clicar em "Honda" antes de capturar o onboarding.** Não é encenação: é o estado normal da tela
  meio segundo depois de o usuário chegar nela. Capturar o estado vazio seria tecnicamente fiel e
  comunicativamente inútil.
- **`insumos.png` em vez de `edicao.png`.** O rascunho do README sugeria "Edição de peças"; a tela
  que faz isso no app se chama **Insumos**. Nome do arquivo e legenda seguem o app, não o rascunho.
- **`deviceScaleFactor: 2`.** 472 kB no total para 4 imagens de 780×1688. Aceitável para um README
  (o GitHub carrega sob demanda) e evita imagem borrada em tela de alta densidade.
- **Script de captura não foi versionado.** Ele depende do Puppeteer, que foi removido; deixá-lo no
  repositório criaria um script quebrado. Se um dia as capturas precisarem ser refeitas, o
  procedimento está descrito nesta tarefa.

## O Que NÃO Foi Feito (e Por Quê)

- **Otimização para WebP:** exigiria outra dependência para poupar ~200 kB num README. Não compensa.
- **Captura em tema claro:** o app abre no tema escuro, que é o que o usuário vê. Duplicar as
  imagens dobraria o peso para mostrar a mesma informação.
- **Capturas das telas de Mão de Obra e Ajustes:** o rascunho pedia 4 imagens; mais que isso vira
  galeria e dilui o que importa.

## Aprendizados Para o Projeto

- **A fixture de desenvolvimento é um ativo de documentação, não só de teste.** Ela deu um app
  populado com dados plausíveis e zero dado real — exatamente o que uma captura para README precisa.
- **Automação de captura tem uma armadilha de estado:** a mesma rota renderiza telas diferentes
  conforme o `localStorage`. Screenshot automatizado precisa declarar de qual estado ele parte, ou
  captura silenciosamente a tela errada — foi o que aconteceu na primeira tentativa do onboarding.
- **Node resolve `import` de pacote a partir da pasta do script, não do diretório de trabalho.**
  Script fora da árvore do projeto não enxerga o `node_modules` dele.
