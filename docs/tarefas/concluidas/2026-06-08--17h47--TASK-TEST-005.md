O que muda:

src/pages/onboarding/passos/PassoModelo.test.tsx [NOVO]
Testes de renderização e interação para o passo de escolha da moto.
Técnica: Mockar o hook usePerfil para prover o estado e dispatch, e mockar catalogoModelos para ter massa de dados controlada (ex: marca com 1 modelo, marca com múltiplos modelos). Mockar useOnboarding para isolar o passo.
Cobertura:
Selecionar marca lista os modelos corretamente.
Selecionar uma marca que só possui 1 modelo auto-seleciona esse modelo.
Trocar de marca limpa o modelo previamente selecionado.
Avançar dispara o dispatch gravando moto.marca e moto.modelo no perfil e chama irParaProximo.
Propriedade podeContinuar (enviada ao PassoLayout) só fica verdadeira com modelo selecionado.
src/pages/onboarding/passos/PassoMaoDeObra.test.tsx [NOVO]
Testes de renderização para o passo de ajuste de mão de obra.
Técnica: Mockar usePerfil com um perfil MVP contendo serviços avulsos que necessitam estimativa de M.O. e useOnboarding.
Cobertura:
Lista corretamente os serviços avulsos (sem valor oficial) como cards M.O.-only.
O total dinâmico (que usa somarMaoDeObraEfetiva) inicia em zero (ou valor correto sem estimativa ligada) e sobe ao ligar a estimativa global no ControleEstimativaMaoDeObra.
Verifica a interação com o botão de estimativa global.
Critérios de aceite:

Ambos os arquivos de teste passam perfeitamente localmente (npm run test).
Typecheck sem erros (npx tsc --noEmit).
Os cenários descritos na issue REV-003-A05 (PassoModelo auto-selecionando e PassoMaoDeObra dinâmico) são validados.
Impacto: Apenas arquivos de teste adicionados. Sem risco para código em produção.

Dependências novas: Nenhuma.

Decisão Técnica Importante (Nota Técnica): O requisito menciona: "Para testar isolado, exportar um helper/provider de teste do OnboardingCtx OU renderizar dentro de MemoryRouter + FluxoOnboarding na rota correspondente". Decidi por uma terceira via mais limpa: vamos fazer o mock do próprio hook useOnboarding via vi.mock('../FluxoOnboarding', () => ({ useOnboarding: ... })). Isso evita termos que exportar contextos privados no código de produção e também evita a complexidade de renderizar toda a árvore de roteamento do FluxoOnboarding só para testar um passo isolado.
