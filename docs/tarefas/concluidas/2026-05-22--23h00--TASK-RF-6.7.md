## Análise de Impacto

**Data da análise:** 22/05/26

### Mudança Proposta

Os 4 campos de `moto.kmUltimaTrocas` (oleo, pneuDianteiro, pneuTraseiro, kitRelacao) eram gravados no perfil mas nenhuma função de `calculos.ts` os lia. O `proximaTrocaKm` em `calcularCpkPorPeca` usava `Math.ceil(kmAtual / intervalo) × intervalo` - presumia troca em múltiplos exatos do intervalo desde 0 km. RF-6.7 fez o km da última troca ancorar o cálculo do ciclo de cada peça (Opção B - custo cíclico).

### Descoberta importante

`manutencao.total` é calculado como `(Σ cpk) × kmAnual`, não `Σ custoAnual`. Para manter a consistência, `cpk` passou a ser derivado de `custoAnual` (`cpk = custoAnual / kmAnual`) - assim `Σcpk × kmAnual = ΣcustoAnual`.

### Decisão em Aberto (resolvida)

**Como o km da última troca afeta o custo?** Resolvida pelo humano: **Opção B** - custo cíclico ancorado no km da última troca (vs. Opção A - só corrige `proximaTrocaKm`, mantendo o total amortizado). Trade-off aceito: o total oscila de um ano para o outro conforme o ciclo; mitigado no futuro pelo ajuste manual de frequência (ADR-006, decisão 8).

## Decisões Tomadas

- **Opção B (custo cíclico) sobre Opção A (só corrige proximaTrocaKm):** decisão do humano. A Opção A seria quase um no-op (`proximaTrocaKm` não é exibido); a Opção B é o que a ADR-006 formaliza.
- **`cpk` passou a ser derivado de `custoAnual`:** `cpk = custoAnual / kmAnual`. Necessário para manter `manutencao.total = (Σcpk) × kmAnual` consistente com a soma dos `custoAnual`. Para peças no fallback o valor é idêntico ao anterior (`preço/intervalo`).
- **`calcularCpkPorPeca` convertida para objeto de opções:** a função tinha 10 parâmetros posicionais; adicionar `kmUltimaTrocas` como 11º seria pior. A conversão **absorveu a TASK-REF-22**.
- **Fallback quando km não informado:** `trocasNoAno = kmAnual / intervalo` (amortizado) - mantém o comportamento anterior intacto para peças sem km registrado.

## O Que NÃO Foi Feito (e Por Quê)

- **`kmMotorRefeito` alimentando o cálculo:** fora de escopo. As retíficas são `servicosIndependentes` (calculadas por `calcularCustoRevisaoAnual`, não `calcularCpkPorPeca`). Fica para tarefa futura, junto de TASK-RF-6.10 (split do "fazer motor").
- **DT-15 (vínculo `ServicoIndependente ↔ Peça`):** permanece aberta. RF-6.7 resolveu o gap relacionado `kmUltimaTrocas ↔ Peça` com um mapa explícito, mas o vínculo serviço↔peça da DT-15 é outro e continua válido.
- **Remover `calcularCpkPeca`:** deixou de ser usada em produção, mas removê-la seria refatoração fora de escopo.

## Aprendizados Para o Projeto
- O custo de manutenção por peça agora é **cíclico**: depende de onde o veículo está no ciclo de cada item. Quem informar um km de última troca verá o total oscilar entre anos - é intencional (Opção B), não bug.
- Sempre que `custoAnual` de uma peça mudar de fórmula, `cpk` precisa acompanhar (`cpk = custoAnual / kmAnual`), senão `manutencao.total` (que soma `cpk`) fica inconsistente com a soma das linhas.
- O fallback amortizado é a rede que garante retrocompatibilidade: peças sem km informado calculam exatamente como antes.
