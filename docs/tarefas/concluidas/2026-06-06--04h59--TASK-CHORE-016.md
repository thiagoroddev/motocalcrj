## Tratamento da Revisão Independente

### Verificação da sugestão

A duplicação das chaves era procedente: o namespace de perfil aparecia no serviço, no bootstrap DEV e em testes. Embora o impacto imediato fosse restrito ao desenvolvimento, uma futura alteração poderia deixar a fixture incompatível com o storage sem erro de compilação.

### Resolução

- `src/services/perfilStorage.ts` passou a exportar `CHAVES_PERFIL_STORAGE` como fonte canônica das chaves de presets, preset ativo e preservação de dados corrompidos.
- `LocalStoragePerfilStorage`, `fixtureDesenvolvimento.ts`, `fixtureDesenvolvimento.test.ts`, `perfilStorage.test.ts` e `App.smoke.test.tsx` passaram a consumir essas constantes.
- Os únicos literais restantes estão no próprio JSON da fixture, onde são propriedades do formato persistido.

O teste da fixture real acessa o JSON pelas constantes canônicas. Assim, uma futura mudança de chave sem atualização da fixture passa a falhar no teste em vez de degradar silenciosamente o bootstrap DEV.

## Aprendizados Para o Projeto

- Bootstrap exclusivo de desenvolvimento deve terminar antes da montagem quando alimenta estado lido sincronamente pelo provider.
