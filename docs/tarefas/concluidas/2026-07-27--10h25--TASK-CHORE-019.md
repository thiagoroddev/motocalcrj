## Decisões Tomadas
- **Sem migração de dados.** Perfis em `estimamoto:v0:*`/`motocalc:v5:*`, tema em `motocalc:tema` e backups `estimamoto-backup` viram lixo ignorado: caem no onboarding / "arquivo inválido". Decisão do humano — o app só existe no link novo, então não há base instalada a proteger. Escrever migração aqui seria código morto no dia 1.
- **Namespace `motocusto:v0:*` mantém a versão 0.** O que mudou foi o namespace, não o schema; `VERSAO_SCHEMA_ATUAL` continua 0.
- **Chaves antigas não são apagadas do `localStorage`.** Ficam órfãs e nunca lidas (mesma conclusão da TASK-REF-30). Varrer storage alheio custaria código para zero benefício.
- **Registros históricos preservados:** `docs/tarefas/concluidas/*`, `REV-002`, `REV-004` (incluindo a menção a `motocalcrj.vercel.app`, verdade na época), `ADR-010` e `trash-drafts-ignore/`. Renomear apagaria o rastro de que o app já se chamou MotoCalcRJ/EstimaMoto — e uma ADR registra a decisão como ela foi tomada.
- **URLs do Figma preservadas:** `design/indices-links-tela-figma.md` (14 links) aponta para o arquivo real `MotoCalc--Copy-`; reescrever produziria links quebrados. `design_completo_figma_inconsistente.md` descreve aquele protótipo e ficou intacto pelo mesmo motivo.
- **`setup-inicial.md` linhas 15-16** (`npm create vite@latest motocalc`) mantidas: registram o comando realmente executado no scaffold.
- **Branch `motocalcrjv1` e repo `estima-calc` mantidos:** infraestrutura; renomear obrigaria a trocar a Production Branch na Vercel e invalidaria links do GitHub, sem efeito para o usuário.

## O Que NÃO Foi Feito (e Por Quê)
- **Ícones/splash do PWA:** as artes (`pwa-*.png`, `apple-touch-icon.png`) não têm o nome escrito. Se ganharem wordmark, refazer.
- **Renomear a pasta do repositório local** (`estima-moto`): fora do escopo, quebraria remotes e caminhos da máquina.

O risco do rename (perda silenciosa de perfis/tema) foi identificado na onda 1, apresentado ao humano e aceito por ele na onda 2 — não foi um efeito colateral despercebido. ## Aprendizados Para o Projeto
- Rename de produto ≠ rename de identificador: nome visível muda quando o dono quiser; chave de storage e formato de backup são contrato com dados já gravados. Quando não há base instalada, o contrato não vale nada — mas essa é uma decisão de produto, não uma suposição do executor.
- Centralizar chaves numa constante (`CHAVES_PERFIL_STORAGE`) transformou a troca de namespace em uma linha; o único ponto que exigiu edição manual foi a fixture DEV, exatamente a dívida apontada na TASK-CHORE-016.
- A varredura do rename expôs docs defasados (`estimamoto:v1` desde a TASK-RF-7.2). Renomear em massa é uma boa hora para reconciliar documentação com o código.
