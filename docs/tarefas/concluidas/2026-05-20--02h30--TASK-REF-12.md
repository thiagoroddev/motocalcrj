## Planejamento Aprovado

### Objetivo

Corrigir três bugs confirmados em `src/utils/calculos.ts` (arquivo autorizado para modificação por ADR-004):

1. **Bug Honda (modo autorizadas):** fórmula baseada em tempo `(ciclo/meses)*12` subestima ~2,4× para entregadores intensos. Fix: `(ciclo/36000)*kmAnual`.
2. **Bug overrides ignorados:** `revisaoAutorizadaOverrides` armazenados no perfil nunca são aplicados no cálculo. Fix: aplicar ao `custoCicloCompleto` antes de calcular.
3. **Modo independentes desatualizado:** usa `precoMaoDeObraIndependente × frequência` (campos planos abandonados). Fix: `∑ (serviço.precoMaoDeObra / serviço.intervalKm) × kmAnual` apenas para serviços com `ativo: true`.

## Decisões Tomadas

- **Override aplicado por índice (DT-13):** mantida a estrutura existente. A fragilidade de índice é risco aceito array Honda é estável (7 revisões fixas do manual). DT-13 fechado.
- **36000 km como divisor:** span total do ciclo Honda Pop 110i (7 revisões: 1k + 6k + 12k + 18k + 24k + 30k + 36k km). Constante codificada correta para Pop 110i, precisaria de parâmetro se outros modelos tiverem ciclos diferentes.
- **`perfilPadrao` importado no test:** necessário para montar mock de `PerfilUsuario` sem duplicar a estrutura completa.

## O Que NÃO Foi Feito

- `precoMaoDeObraIndependente` e `frequenciaRevisaoKm` não foram removidos do tipo `PerfilManutencao` mantidos por backwards-compat e porque a UI ainda pode referenciar esses campos.
- Migração do identificador de override de `index` para `intervaloKm` adiado (DT-13 fechado como "risco aceito").
- ~~`resolverIntervaloPeca` usar `ServicoIndependente.intervalKm` como fonte canônica~~ estava no escopo ADR-004 mas não entrou no plano aprovado da primeira execução. **Corrigido no Adendo abaixo.**

## Aprendizados

- `calcularCustosPorCategoria` recebe `PerfilUsuario` completo montar mock full é custoso; usar `perfilPadrao` como base com spread simplifica muito.
- O divisor `36000` é específico do ciclo Honda Pop 110i. Se outros presets forem adicionados com ciclos diferentes, a constante precisará virar parâmetro do preset.

## Adendo Gap ADR-004: `resolverIntervaloPeca` usa `ServicoIndependente.intervalKm`

**Data:** 20/05/26  
**Motivo:** A ADR-004 previa que peças com `id` correspondente a um `ServicoIndependente` ativo usariam `ServicoIndependente.intervalKm` como intervalo canônico. Este item não entrou no plano aprovado da execução inicial e foi identificado como gap antes de iniciar TASK-RF-6.1.

### O que foi planejado (ADR-004)

> As peças continuam calculadas pelo fluxo `calcularCpkPorPeca`, mas agora usando `ServicoIndependente.intervalKm` como intervalo canônico (quando houver serviço mapeado), em vez do `vidaUtilKm` do preset.

### Mudanças aplicadas

| Arquivo | Mudança |
|---|---|
| `src/utils/calculos.ts` | `resolverIntervaloPeca`: novo param `servicosIndependentes?: ServicoIndependente[]`; antes do fallback preset, verifica serviço ativo com mesmo `id` |
| `src/utils/calculos.ts` | `calcularCpkPorPeca`: novo param `servicosIndependentes?: ServicoIndependente[]`; repassa para `resolverIntervaloPeca` |
| `src/utils/calculos.ts` | `calcularCustosPorCategoria`: passa `perfil.servicosIndependentes` para `calcularCpkPorPeca` |
| `src/utils/calculos.test.ts` | 2 novos testes: serviço ativo substitui preset; serviço inativo cai no preset |

### Nova ordem de prioridade em `resolverIntervaloPeca`

```
1. personalizado + override.intervaloKmEditado
2. personalizado + média de registros
3. ServicoIndependente.intervalKm  (ativo, id coincide)  ← novo
4. Preset (intervaloKmEntrega / intervaloKm / vidaUtilKm)
```

### Testes pós-adendo

- `tsc --noEmit`: limpo
- `npm run test`: **98 verdes** (+2 vs 96 anteriores)

### Decisão

Todos os parâmetros novos são opcionais com default `[]` chamadas externas existentes não quebram. `ativo: false` mantém o comportamento anterior (cai no preset), garantindo que serviços desativados pelo usuário não afetam o cálculo de peças.
