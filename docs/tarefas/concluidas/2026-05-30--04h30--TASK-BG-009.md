## Causa-raiz

A escala `max-w-*` do Tailwind v4 estava **corrompida** por colisão de chaves: os tokens
`--spacing-sm/md/lg/xl` (8/16/24/32px) definidos em `src/index.css` compartilham as chaves
`sm/md/lg/xl` com a escala de container que `max-w-*` resolve. Resultado no CSS compilado:

| classe | compilava como | correto |
|---|---|---|
| `max-w-sm` | 8px | 24rem |
| `max-w-md` | 16px | 28rem |
| `max-w-lg` | **24px** | 32rem |
| `max-w-xl` | 32px | 36rem |

O `DialogContent` usa `max-w-[calc(100%-2rem)] sm:max-w-lg`:
- **< 640px** (mobile): vale `max-w-[calc(100%-2rem)]` → largura correta (por isso não bugava no celular).
- **≥ 640px** (PC/notebook/tablet): entra `sm:max-w-lg` = 24px → o modal colapsava na "tira fininha" dos prints.

Diagnóstico fechado **lendo o CSS compilado** (`dist/assets/*.css`), sem necessidade de
reproduzir no browser. Confirmado que **não** era o conflito clássico shadcn de `transform`
(centralização `translate-*` e animação `enter` usam propriedades distintas no Tailwind v4) nem
containing-block de ancestral (nenhum `transform/filter/will-change` em seletor estrutural).

## Decisão

Humano escolheu **fix pontual agora + task de raiz separada**. O fix pontual usa **valores
arbitrários** (`max-w-[32rem]` etc.) que ignoram o sistema de tokens, em vez de redefinir
`--container-*` no `@theme` (testado: o `--spacing-*` continua vencendo) ou renomear os tokens
de spacing (alto churn, ~71 usos).

## Implementação

- `src/components/ui/dialog.tsx`: `sm:max-w-lg` → `sm:max-w-[32rem]` + comentário apontando a colisão e a TASK-BG-009.
- `src/components/ui/sheet.tsx`: variantes `left`/`right` `sm:max-w-sm` → `sm:max-w-[24rem]` + comentário. (Sheet `bottom` do PopupAjuda não usa `max-w`, já estava OK.)
- `src/components/detalhamento/PopoverDetalhesPeca.tsx`: `sm:max-w-xl` → `sm:max-w-[36rem]` + comentário.

Cobre todos os pop-ups: DialogConfirmacao, DialogEdicaoCusto (todos os alvos), PopoverDetalhesPeca,
ajuda + edição de gasto em SecaoImprevistos, PopupAjuda — todos consomem os 3 primitivos editados.

## Decisões / Cuidados

- Warnings do IDE sugerindo canonicalizar `max-w-[32rem]`→`max-w-128` foram **deixados de propósito**: o valor arbitrário é imune ao sistema de tokens que causou o bug; o comentário documenta o porquê.
- `min-w-[420px]`/`min-w-[320px]` pré-existentes em PopoverDetalhesPeca não foram tocados (fora de escopo).
- Mobile (`max-w-[calc(100%-2rem)]`) intacto — só a faixa `sm:` mudou.
