## Problema

`npx tsc --noEmit` falhava com 6 erros em `src/utils/calculos.test.ts`. O import do JSON `pop110i.json` infere `pneus[].posicao` como `string`, mas `PneuPreset.posicao` é o union `'dianteiro' | 'traseiro'`. Ao passar `pop110i` como `PresetMoto` em 6 chamadas (`calcularCpkPorPeca`, `calcularCustosPorCategoria`), o typecheck quebrava. `npm run test`/`lint` passavam - só o `tsc` ficava vermelho. Pré-existente (confirmado via `git stash` na RF-6.16).

## Fix

- Alias tipado único após o import: `const presetPop110i = pop110i as PresetMoto;` (mesmo padrão de cast que a produção já usa ao carregar presets via `import.meta.glob`).
- As 6 chamadas passaram a usar `presetPop110i`. As leituras read-only do JSON (`pop110i.pecas`, `.pneus`, `.revisaoAutorizada`) seguem usando `pop110i` cru.

## Verificação

- `npx tsc --noEmit`: **limpo** (0 erros) - primeira vez no projeto após a introdução desses testes.
- `npm run lint` verde; `npm run test` 166 verdes.
