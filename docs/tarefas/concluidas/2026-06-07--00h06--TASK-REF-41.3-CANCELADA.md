- **ADR-018:** remove o modo de uso e seus vestígios visuais; um único padrão profissional editável.
- **Status:** aceita.

## Diagnóstico Verificado

- O Passo 4 (`src/pages/onboarding/passos/Passo4.tsx`) é apenas um card informativo
  ("Uso profissional e intenso"), sem estado nem escolha. É o último vestígio visual de `PerfilUso`.
- Navegação e progresso vivem em `src/pages/onboarding/onboardingUtils.ts`:
  `MAPA_PROXIMO` (`'3' → '4' → '5'`), `MAPA_ANTERIOR` (`'5' → '4' → '3'`) e `CONFIG_PASSOS`
  (labels "PASSO X DE 9" + percentual).
- As rotas estão em `FluxoOnboarding.tsx` (`<Route path="4" .../>` + import de `Passo4`).
- O smoke (`App.smoke.test.tsx:167,178`) atravessa o Passo 4 duas vezes
  (`findByText('Uso profissional e intenso')`), inclusive no teste de Voltar/troca de ano.
- `CONFIG_PASSOS` já tem inconsistências pré-existentes: `'6/responsabilidade'` rotula
  "PASSO 8 DE 9" e os percentuais não são monotônicos.

## Planejamento Proposto

  - remover a chave `'4'` de `CONFIG_PASSOS`, `MAPA_PROXIMO` e `MAPA_ANTERIOR`;
  - religar `MAPA_PROXIMO['3'] = '5'` e `MAPA_ANTERIOR['5'] = '3'`;
  - renumerar todos os labels para "PASSO X DE 8" e recalcular percentuais coerentes
    (1,2,3 = rotas 1/2/3; passo 4 = rota 5 + 5trocas; passo 5 = rota 6 + financiamento/aluguel/
    responsabilidade; passo 6 = rota 7; passo 7 = rota 8; PASSO FINAL = rota 9 + confirmacao);
  - de quebra, corrigir o label errado de `'6/responsabilidade'` e tornar os percentuais monotônicos.
- `src/pages/onboarding/FluxoOnboarding.tsx`: remover o `import { Passo4 }` e a `<Route path="4">`.
  O catch-all `path="*"` já redireciona `/onboarding/4` para `/onboarding/1`, então a rota some sem
  deixar 404.
- `src/pages/onboarding/passos/Passo4.tsx`: **excluir o arquivo** (ação destrutiva — coberta por esta
  aprovação).

## Critérios de Aceite

- O Passo 4 informativo não existe mais: arquivo removido, rota removida, sem import órfão.
- `/onboarding/4` não é alcançável (redireciona para `/onboarding/1`).
- O onboarding anuncia 8 passos, com labels e percentuais coerentes e monotônicos.
- Navegação íntegra: avançar do passo de ano vai ao passo de KM; Voltar do passo de KM volta ao ano.
- Nenhuma referência visível a entrega/passageiro/"referência de uso" no fluxo.
- `npm run test`, `npm run lint`, `npm run typecheck` e `npm run build` passam de verdade.
- DT-18 encerrada; docs vivos (contexto, glossário) coerentes com 8 passos.

## Riscos

- **Renumeração inconsistente:** mitigar recomputando todos os labels/percentuais de uma vez e
  cobrindo a navegação por teste.
- **Smoke frágil:** mitigar reescrevendo o trecho de Voltar/troca de ano a partir do novo passo.
- **Churn com a RF-6.28:** esta tarefa vai a 8 passos e a RF-6.28 reintroduz um Passo 4 (vida útil),
  voltando a 9. É a fatia mínima para fechar a DT-18 sem esperar a feature maior — decisão de produto
  registrada na ADR-018.

## Decisões a Confirmar

1. **Seguir com a fatia mínima (8 passos agora, RF-6.28 volta para 9 depois)?** Recomendo sim: fecha
   a DT-18 já; a RF-6.28 é feature separada e maior.
2. **Aproveitar para corrigir as inconsistências pré-existentes de label/percentual do
   `CONFIG_PASSOS`** (responsabilidade mislabeled, percentuais não monotônicos)? Recomendo sim, já que

  TASK-RF-6.28, sem mudar a contagem de 9 passos.
