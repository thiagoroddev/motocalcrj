## Decisões Tomadas

- **Sem ancoragem por data:** o custo da bateria é sempre amortizado (CPK estável, filosofia da ADR-016). A ancoragem fazia o custo "lumpy" (0/cheio) e **sumir do detalhamento** quando 0 — comportamento consistente com km, mas confuso para a bateria. Decisão do humano: simplicidade.
- **Legado mantido (não removido):** o campo `perfilManutencao.bateria.ultimaTrocaAnoMes` (null) e a action `SET_BATERIA_ULTIMA_TROCA` ficam **inertes** no modelo (evita churn em schema/fixtures; não-quebrável). A regra CSS do `::-webkit-calendar-picker-indicator` (index.css) fica (sensata para qualquer input de data futuro).

## O Que NÃO Foi Feito (e Por Quê)

- **Remover o campo `ultimaTrocaAnoMes` + a action do modelo:** deixado como legado inerte para não cascatear em schema/tipo/reducer/fixtures (não-quebrável; removível numa limpeza futura).

- **Simplicidade > consistência aqui:** ancorar a bateria por data (como km) era "consistente", mas a consequência (sumir quando não vence no ano + UI de data) confundia. Para um estimador de orçamento, **amortizar sempre** (CPK estável) é o melhor — a vida útil em anos (editável) basta.
