## Decisões Tomadas

- **SecaoManutencao adicionada ao plano durante execução:** sem este componente a página ficaria em ~162 linhas pós-Prettier; com ele, ~199. A adição foi documentada no `em-andamento.md` antes de executar.
- **Meta revisada de ≤ 150 para ≤ 200 linhas:** a meta de ≤ 150 foi estabelecida antes de considerar o impacto da Prettier na formatação do JSX expandido. O Prettier reformata cada prop de componente em linha própria, tornando 150 linhas inatingível sem comprometer legibilidade. O resultado final de 199 linhas representa redução de 63% (543 → 199).
- **`Toggle` permanece custom:** shadcn `Switch` usa `bg-background` no thumb; o design atual usa `bg-foreground`. Diferença visual intencional — substituição causaria regressão.
- **`CATEGORIAS_SEM_EXPANSAO` (array-driven):** as 4 categorias sem accordion (internet, seguro, alimentação, financiamento) seguem o mesmo padrão de render — extraídas para um array de configuração e renderizadas em `.map()`. Reduz de 48 para 14 linhas mantendo tipo-segurança via `ChaveCategoriaSemExpansao`.
- **`toggleFiltro` permanece na página:** contém a cascata `manutencao → revisao = false`. Mantida visível no nível da página para facilitar manutenção.
- **Sem ADR nova:** a refatoração segue o padrão já estabelecido por TASK-REF-01 e documentado via ADR-001.

## Aprendizados para o Projeto

- A Prettier expande props de componente React em linhas separadas quando o total ultrapassa o `printWidth`. Metas de contagem de linhas para páginas com muitos componentes JSX devem considerar esse efeito — ≤ 200 linhas é mais realista que ≤ 150 para páginas com 7+ seções.
- O padrão array-driven para categorias repetitivas (mesmo template, dados diferentes) reduz linhas e torna trivial adicionar/remover categorias: basta editar o array `CATEGORIAS_SEM_EXPANSAO`.
