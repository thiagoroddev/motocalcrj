## Decisões Tomadas

- **Sub-passo sem alterar contagem total:** '5trocas' usa label "PASSO 5 DE 9" com percentual 60 — o usuário percebe como continuação do passo 5, sem mudar a progressão anunciada de 9 passos.
- **Toggle button sem shadcn Checkbox:** Checkbox não está instalado; o padrão de botão com borda `border-primary bg-primary/20` + ícone ✓ inline é consistente com Passo4 e evita nova dependência.
- **`podeContinuar` sempre true:** Passo opcional — nenhum dos itens é obrigatório. Marcar nada é válido (não dispara `MARCAR_TROCAS_REVISAO`).
- **`MARCAR_TROCAS_REVISAO` só disparado se `marcados.size > 0`:** Evita um dispatch no-op quando o usuário não marca nada — não é incorreto, mas é desnecessário.
- **Motor usa `SET_MOTOR_REFEITO` separado:** O campo é `number | null`, não pertence a `KmUltimaTrocas`. Tratado com boolean local `motorMarcado` e dispatch próprio.
- **kmRevisao = `kmUltimaRevisao ?? 0`:** Quando o usuário não informou km da última revisão, os itens marcados recebem km 0. Nota explicativa exibida no passo.

## O Que NÃO Foi Feito (e Por Quê)

- **Pular '5trocas' quando kmUltimaRevisao é null:** Exigiria passar `kmUltimaRevisao` para `getProximoPasso`, mudando a assinatura que hoje só aceita `SituacaoMoto`. O custo de refatoração não justifica o ganho — o passo com nota é aceitável.

## Aprendizados Para o Projeto

- Para passos opcionais no onboarding, `podeContinuar` fixo em `true` comunica a intenção melhor do que uma variável derivada que nunca muda.
