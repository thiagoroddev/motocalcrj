- **Observações:** `useCustos` resolve presets por convenção de string usando `perfil.moto.modelo`; o `id` do catálogo precisa bater com o arquivo `src/presets/<id>.json`.

## Planejamento Aprovado

**O que muda:**
- `src/data/catalogoPresets.test.ts`: novo teste de contrato entre `CATALOGO` e `src/presets/*.json`.
- O teste importa `CATALOGO`, lista os presets reais com `import.meta.glob` e garante que todo id do catálogo tem JSON correspondente.
- O teste também valida que o id interno do preset bate com o nome do arquivo, se esse campo existir.

**Critérios de aceite:**
- O teste passa hoje com `pop110i`. OK
- O teste falha se um modelo do catálogo ficar sem `src/presets/<id>.json`. OK
- `npm run test`, `npm run lint` e `npm run build` verdes. OK

**Impacto:** camada de dados/testes; sem alteração de comportamento em runtime.
**Riscos:** duplicar a convenção do glob de presets no teste; mitigado porque o teste existe justamente para proteger essa convenção.
**Dependências novas:** nenhuma.

## Decisões Tomadas

- A guarda ficou em teste automatizado, sem alterar comportamento de runtime.
- Não foi criada UI de fallback nesta tarefa; o aceite pedia bloquear o drift catálogo↔preset antes de chegar ao app.
- A verificação opcional de `preset.id` só roda quando um preset futuro declarar esse campo na raiz.

## O Que NÃO Foi Feito (e Por Quê)

- Não foi alterado `useCustos.ts`: a falha não é no hook em si, mas na ausência de contrato automatizado para a convenção de nomes.
- Não foi adicionada dependência nova: Vitest + `import.meta.glob` já cobrem o caso.
- Não foi criado documento de domínio: a convenção agora está protegida por teste, que é a fonte executável do contrato.
