## Decisões Tomadas
- **Testes isolados com fixture, não smoke, para a `SecaoManutencao`/popovers:** o acordeão de Manutenção vem colapsado e o label varia (`Manutenção (parcial)`), o que tornaria o smoke frágil. Render isolado com `expandido=true` é determinístico.
- **`DialogEdicaoCusto`/estimativa por smoke:** o conteúdo do popup (`ConteudoEstimativaMaoDeObra`) é interno e a montagem isolada do dialog exigiria props demais; o chip está no card do topo (sem acordeão), então o smoke clica e valida a fiação real sem fixture.

## O Que NÃO Foi Feito (e Por Quê)
- **Não exportei `ConteudoEstimativaMaoDeObra` só para teste:** o smoke do chip→popup já cobre o Segmentado end-to-end sem expor interno.
- **Não cobri exaustivamente todos os ramos de `DialogEdicaoCusto`** (combustível, seguro, etc.): fora do escopo desta task (foco: manutenção/REF-32.6).

## Aprendizados Para o Projeto
- **Render isolado > smoke quando o estado de UI atrapalha:** acordeão colapsado/label dinâmico tornam o smoke frágil; controlar props dá testes estáveis. Mas para fiação que cruza vários componentes (chip→popup), o smoke é o caminho certo.
- **Radix Dialog testa bem em jsdom** via `open`/`aberto` — sem trigger, o conteúdo entra no portal e `screen` acha.
