# TASK-BG-001 — Polimento UI: PaginaVidaUtil e PaginaAjustes

**Tipo:** Bug/Polish  
**Concluída em:** 2026-05-20 15:02  
**Esforço real:** ~1h

## Problema

As abas "Preço Peças" e "Ajustes" foram implementadas funcionalmente mas ficaram com problemas visuais que destoavam do restante do app:

- **PaginaVidaUtil (CardItemPreco):** dois labels fixos embaixo de um input editável para "Original" e "Paralela" — não fazia sentido editar um valor mas ver dois rótulos distintos; input direito (vida útil) sem distinção visual de read-only; falta de nota explicando onde alterar km.
- **PaginaAjustes:** inputs com larguras inconsistentes, espaçamento excessivo entre label e input, seções sem bg-card, botões Stepper com apenas 28px de altura (< min-h-touch), botões Segmentado sem min-h-touch, Separators desnecessários.

## Solução

### PaginaVidaUtil — CardItemPreco

- Substituiu os dois labels fixos por um **toggle segmentado Original/Paralela** que mostra o preço de cada opção dentro do próprio botão e altera `perfilPecasOverride` ao clicar.
- Ao trocar de perfil, `precoEditado` é resetado para evitar override obsoleto.
- Input direito (vida útil) convertido para `div` read-only com `border border-muted bg-muted/20 text-muted-foreground/60 cursor-default`.
- Nota "Alterar na aba M. Obra" adicionada abaixo do div.
- `temOverride` expandido para cobrir `perfilPecasOverride` além de `precoEditado`.

### PaginaAjustes

- Todas as `<section>` receberam `bg-card rounded-lg p-md` (card visual uniforme com o resto do app).
- Todos os `<Separator />` removidos (substituídos pelo espaçamento do card).
- Todos os `Input` padronizados para `w-28`.
- Botões `Stepper`: `w-7 h-7` → `w-10 h-10 text-lg` (≥ min-h-touch).
- Botões `Segmentado`: adicionados `min-h-touch flex items-center justify-center`.
- Botão CTA reset: adicionado `min-h-touch`.
- Espaçamento geral: `space-y-6` → `space-y-3` (cards já provêm separação visual).

Auto-revisão IA + observações reportadas pelo humano (screenshot + descrição de comportamento)

### ✅ Bom
- `Segmentado` e `Stepper` são componentes bem encapsulados, com interface mínima e sem estado interno desnecessário
- `trocarPerfil` tem lógica de "reset para global quando igual ao global" correta (`RESET_PECA_OVERRIDE` com `campo: 'perfilPecas'`)
- Convenção de idioma PT-BR mantida em todos os novos símbolos
- Nenhum `any`; tipos explícitos em todas as interfaces locais
- `COMPONENTES_TROCA` corretamente definida fora do componente (sem recriação por render)
- `useEffect` para sincronizar `preco` local com `precoEfetivo` é caso justificado (buffer de digitação + reset externo via dispatch)
- `CardCombustivel` preserva edição local corretamente ao fazer blur (dispatch só no blur, não no onChange)

### 🔴 Bloqueante

**Labels no toggle Original/Paralela mostram preço fixo do preset, não o preço salvo**
- Onde: [src/pages/PaginaVidaUtil.tsx:204-206](src/pages/PaginaVidaUtil.tsx#L204-L206)
- Problema: `(p === 'original' ? precoOriginal : precoParalela).toFixed(2)` — sempre exibe o preço do preset. Após o usuário editar o preço para R$ 47,00 enquanto está na opção "Original", o botão "ORIGINAL" continua exibindo o preço padrão (ex: R$ 35,00). A UI contradiz o estado real salvo.
- Solução: Para o botão do perfil ativo, mostrar `override?.precoEditado ?? precoBase` calculado para aquele perfil. Para o botão inativo, manter o preço do preset (indica o que o usuário obteria ao trocar). Exemplo: `p === perfilEfetivo ? (override?.precoEditado ?? (p === 'original' ? precoOriginal : precoParalela)) : (p === 'original' ? precoOriginal : precoParalela)`.

**Edição de preço apagada silenciosamente ao alternar toggle de perfil**
- Onde: [src/pages/PaginaVidaUtil.tsx:175](src/pages/PaginaVidaUtil.tsx#L175)
- Problema: `if (override?.precoEditado != null) dispatch({ type: 'RESET_PECA_OVERRIDE', id, campo: 'preco' })` é disparado toda vez que o usuário clica no toggle. O `precoEfetivo` reverte ao preset; o `useEffect` (linha 160) sincroniza o input com o valor revertido. O usuário perde sua edição sem aviso, sem possibilidade de desfazer — o ícone de reset fica invisível porque o override foi limpo.
- Nota arquitetural: `precoEditado` é um campo único (`number | null`) compartilhado entre os perfis Original e Paralela. Se o `precoEditado` não for limpo ao trocar de perfil, o preço editado para "Original" (ex: R$ 47) apareceria erroneamente no perfil "Paralela". Isso é um conflito de modelo de dados. Opção A (rápida): manter limpeza + corrigir label (🔴 BG anterior) para comunicar claramente o estado. Opção B (correta): separar `precoEditado` por perfil no tipo `PecaOverride`.
- Solução imediata (Opção A): a limpeza em si é correta; o bug real é que o usuário não vê o que vai perder antes de clicar. Fixar o label (🔴 anterior) resolve 80% da percepção. TASK-BG-002 cobre ambos.

### 🟡 Importante

**Div "Vida útil" visualmente mais fino que o Input ao lado**
- Onde: [src/pages/PaginaVidaUtil.tsx:226](src/pages/PaginaVidaUtil.tsx#L226)
- Problema: O `Input` shadcn tem `h-10` (40px) hardcoded em sua base class + `min-h-touch` externo (48px) → renders a 48px. O `div` read-only usa apenas `min-h-touch` sem `h-10` explícito. Apesar de ambos deverem resultar em 48px, o screenshot do usuário confirma que o div renderiza visivelmente mais baixo. Possível diferença de resolução CSS entre `<input>` e `<div>` com as mesmas constraints no Tailwind v4.
- Solução: Adicionar `h-10` explícito ao div: `className="rounded-input border border-muted bg-muted/20 h-10 min-h-touch text-sm flex items-center px-3 text-muted-foreground/60 select-none cursor-default"`.
- Tarefa gerada: TASK-BG-002 (corrigir junto com os bloqueantes acima por serem no mesmo componente)

**Layout `Linha` cria gap visual excessivo entre label e input em PaginaAjustes**
- Onde: [src/pages/PaginaAjustes.tsx:105-112](src/pages/PaginaAjustes.tsx#L105-L112)
- Problema: `Linha` usa `flex justify-between` com inputs de `w-28` (112px) fixo. Em tela de ~375px com padding lateral de 32px (2×16px), o label tem ~215px de espaço mas frequentemente ocupa apenas 50-100px de conteúdo real. O gap visual entre o fim do texto do label e o início do input é desproporcional, destoando das outras telas que usam grid ou inputs de largura total/metade.
- Tarefa gerada: TASK-REF-13

**Componentes reutilizáveis definidos inline nas pages, fora de `src/components/`**
- Onde: [src/pages/PaginaVidaUtil.tsx:24-234](src/pages/PaginaVidaUtil.tsx#L24-L234) (`IconeReset`, `CardCombustivel`, `CardItemPreco`), [src/pages/PaginaAjustes.tsx:31-112](src/pages/PaginaAjustes.tsx#L31-L112) (`Segmentado`, `Stepper`, `Linha`)
- Problema: 6 componentes com interface bem definida vivem no corpo das pages. `Segmentado` e `Stepper` são especialmente reutilizáveis (aparecem múltiplas vezes na mesma page e são candidatos a uso em outros contextos). Viola o padrão do projeto: componentes com interface própria pertencem a `src/components/`.
- Tarefa gerada: TASK-REF-14

**`PaginaAjustes` implementa header próprio em vez de usar `CabecalhoVoltar`**
- Onde: [src/pages/PaginaAjustes.tsx:125-145](src/pages/PaginaAjustes.tsx#L125-L145) vs [src/components/CabecalhoVoltar.tsx](src/components/CabecalhoVoltar.tsx)
- Problema: Header com `<svg>` inline de voltar duplica exatamente o que `CabecalhoVoltar` já oferece. Duplicação = inconsistência visual futura e manutenção dobrada. A aparência pode divergir quando `CabecalhoVoltar` for atualizado.
- Tarefa gerada: TASK-REF-15

**Altura dos botões do toggle `Segmentado` ainda abaixo do mínimo de toque reportada pelo usuário**
- Onde: [src/pages/PaginaAjustes.tsx:49](src/pages/PaginaAjustes.tsx#L49)
- Problema: TASK-BG-001 adicionou `min-h-touch` ao `Segmentado`, mas o usuário ainda reporta os toggles como finos. O código tem `min-h-touch` na classe, mas o usuário visualiza comportamento diferente. Possível: `min-h-touch` via CSS custom property não está resolvendo corretamente como `min-height` nesse contexto de flex, ou o scroll / container pai está limitando a altura. Necessita verificação visual no browser.
- Solução sugerida: Substituir (ou complementar) `min-h-touch` por `h-12` (48px explícito, sem variável CSS): `className="flex-1 h-12 min-h-touch flex items-center justify-center..."`.
- Tarefa gerada: TASK-BG-002 (pode ser corrigido junto)

### 🟢 Sugestão
- Botões do toggle Original/Paralela em `CardItemPreco` (linhas 193-208) usam apenas `py-2`, sem `min-h-touch`. Como são elementos interativos em contexto mobile, deveriam ter toque mínimo de 48px.
- A estrutura `import.meta.glob('../presets/*.json')` em `PaginaVidaUtil` é idêntica à de outros arquivos. Se mais contextos precisarem dos presets, centralizar em `src/data/` ou num hook evitaria duplicação.
- `dispatch({ type: 'SET_SEGURO', config: { valorAnual: v } })` (linha 343) passa apenas campos parciais. Verificar se o reducer faz merge ou replace; se for replace, os campos omitidos (`tem`, `periodicidade`) podem ser sobrescritos com undefined.
