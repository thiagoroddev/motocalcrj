## Aprendizados Para o Projeto

- **Estratégia Híbrida (banner em spec versionada + delete em docs operacionais) é o padrão certo para sincronizar ADRs de adiamento.** Preserva história sem inflar docs vivas. Vale como template para futuras ADRs do tipo "removido do escopo X".
- **Pointer enxuto > snapshot copiado, para qualquer doc que descreve estrutura técnica.** As 280 linhas de interfaces XII.1 decaíram em poucas semanas após cada REF. As ~20 linhas de pointer + sumário decaem só quando os nomes dos próprios arquivos mudam. Mesma lição da DOC-009 (`calculos-visao.md`), agora aplicada a tipos também.
- **Lista pequena de tipos canônicos: 1 grep + 1 ls antes de citar.** O erro inicial do pointer XII.1 (paths e nomes errados) é recorrente porque a IA "sabe" como esses arquivos deveriam se chamar. Sempre verificar.
- **Bucket próprio para "Adiado por ADR" em MoSCoW** evita conflito semântico com "Won't Have" (não-faremos) ou "Could Have" (faríamos se sobrar tempo). "Backlog (ADR-XXX)" diz exatamente o que é.
- **Sincronização documental pós-ADR grande deve ser orçada com a própria ADR.** ADR-003 (18/05) criou 7 dias de divergência até a sincronização total (DOC-009 + DOC-010). Para o próximo, incluir checklist "varrer docs/dominio + docs/arquitetura + docs/requisitos + docs/contexto-projeto-ai.md" no escopo da ADR ou criar TASK-DOC junto.
