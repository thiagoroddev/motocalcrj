## Análise de Impacto

**Data da análise:** 23/05/26

### Mudança Proposta

A ADR-003 declarou modo único de cálculo (sem Registros, sem toggle predefinidos/personalizado). O mecanismo `modoExibicao` permaneceu no código e a REF-14 reexpôs o toggle "Estimativa sobre dados" em Ajustes - violação direta da ADR-003. REF-18 remove o mecanismo por completo: o campo, a action, todas as ramificações nos cálculos, o toggle na UI e a aba `PaginaRegistros.tsx` (órfã). O app passa a operar em modo único: overrides do usuário sempre se aplicam.

## Decisões Tomadas

- **Migração v7→v8 usa `delete` em vez de destructuring com `_descartado`:** evita o warning `no-unused-vars` que apareceu na primeira tentativa. O `delete` é seguro porque opera num objeto fresco (`{ ...dados.configuracaoDisplay ?? {} }`).
- **`PaginaEstimativa.tsx` perdeu o badge "Modo personalizado ativo" (não estava no plano explicitamente):** o badge dependia de `resultado.modoAtivo` que deixou de existir. Remoção lógica.
- **Override sempre aplica quando presente** (em `resolverIntervaloPeca`/`resolverPrecoPeca`/`calcularCpkPorPeca`): é a leitura coerente da ADR-003 (modo único; o "personalizado" implícito agora é a presença de override).
- **`fonte: 'preset' | 'registro'` mantido em `CustoPeca`:** semântica passa a "tem override". Não renomeado para evitar mexer na UI (`SecaoManutencao` badge "real") fora de escopo.
- **Fixture v6 não foi atualizada para v8:** migração faz o trabalho no carregamento. Mantém o fixture como caso de teste das migrações v6→v7 e v7→v8.
- **REF-19 absorveu o cleanup fora-de-escopo antes desta tarefa rodar:** evita gerar uma terceira tarefa para o mesmo conjunto de itens; concentra todo o cleanup remanescente lá (Strict, com schema migration v8→v9).

## Aprendizados Para o Projeto
- A ADR-003 levou semanas para ser cumprida porque o mecanismo `modoExibicao` estava entranhado em vários cantos (calc, reducer, UI, schema). Quando uma decisão arquitetural só remove uma feature, a limpeza completa precisa ser uma tarefa dedicada (esta) - adiar acumula débito.
- Migrações de schema com `delete` em objeto novo (`{ ...x }; delete novo.campo`) são mais limpas que destructuring com variável "discartada" quando o lint reclama de `no-unused-vars`.
- A leitura coerente de "modo único" da ADR-003 é "override sempre aplica" - não "override nunca aplica". Foi a escolha óbvia, mas vale documentar para que mudanças futuras não regridam.
