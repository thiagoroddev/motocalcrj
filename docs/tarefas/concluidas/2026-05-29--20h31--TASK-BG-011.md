## Contexto / Reformulação

A premissa original da BG-011 ("R$1.500 de M.O. pura da retífica completa está alto") estava **errada**. O campo `ServicoIndependente.precoMaoDeObraIndependente` era **sobrecarregado**: M.O. para serviços normais, mas **valor único peças+M.O.** para excepcionais (retíficas, que não são orçadas separando peça de mão de obra). O nome enganoso gerou o bug-report. Decisão do humano: **Opção A** — renomear o campo para `precoIndependente` (neutro) e **manter os valores** (R$800/R$1.500).

## Implementação

- `src/types/perfil.ts`: `precoMaoDeObraIndependente` → `precoIndependente` + comentário explícito (normal=M.O., excepcional=peças+M.O.).
- `src/context/PerfilContext.tsx`: rename nas constantes (`SERVICOS_INDEPENDENTES_PADRAO`, retíficas) + nas leituras das migrações históricas (v10→v11, v14→v15); novo passo **v20→v21** que renomeia o campo persistido (lê `precoMaoDeObraIndependente` como fallback, preserva valor); `perfilPadrao.schemaVersion` 20→21.
- `src/utils/calculos.ts`, `src/components/mao-de-obra/CardServico.tsx`, `src/pages/PaginaMaoDeObra.tsx`: novo nome.
- `src/fixtures/usuario_teste.json`: chave renomeada + schemaVersion 21.
- Testes: rename + schemaVersion 20→21 + novo teste do passo v20→v21.
- `docs/arquitetura/ADR/ADR-007.md`: adendo registrando o rename (sem reescrever o histórico).
