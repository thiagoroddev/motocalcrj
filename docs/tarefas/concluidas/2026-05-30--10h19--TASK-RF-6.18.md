## Contexto

Com a moto `financiada`, o contador de parcelas restantes não diminuía com o tempo - o usuário editava manualmente. Pior: `parcelasRestantes` era **puramente informativo**; `calcularCustoFinanciamentoAnual` retornava sempre `parcelaMensal * 12`, então o financiamento nunca terminava no cálculo, mesmo após a última parcela.

## Decisões (aprovadas pelo humano em 30/05/26)

1. **Modelagem = Snapshot.** Mantém o input `parcelasRestantes` + grava `dataReferenciaParcelas` (mês ISO do snapshot). O valor de hoje é **derivado**, sem mutar o perfil. Descartadas: mutação periódica (escrita silenciosa) e `dataInicio + parcelasTotais` (mudaria a UX do onboarding e a migração teria de supor uma data inexistente).
2. **Cálculo = Afunilar.** `custoAnual = parcelaMensal × min(12, max(0, restantesHoje))`; zera ao acabar. Descartado: degrau (`× 12` fixo até zerar) - superestima o último ano.
3. **Cerimônia = Strict + ADR.**

Registradas no **ADR-009** (a ADR-008, já existente, é sobre tokens de spacing - sem relação).

### 🟢 Sugestão

- `restantesHoje === 0` com `situacaoMoto` ainda `financiada`: o Detalhamento exibe "R$ X x 0 = R$ 0" + nota "quitado". Funcional, mas o "x 0" é estranho - poderia ocultar a linha "Cálculo anual" quando zera. [PaginaDetalhamento.tsx:353](../../../src/pages/PaginaDetalhamento.tsx#L353)

Só destoaria com troca de fuso entre o snapshot e a leitura (desprezível). Vale anotar a premissa.
