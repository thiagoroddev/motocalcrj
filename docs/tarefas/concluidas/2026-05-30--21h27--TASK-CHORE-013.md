## Decisões Tomadas

- **Ambiente jsdom por-arquivo (docblock), não global:** mantém os 200 testes de cálculo/contexto em `node` (rápidos, sem DOM à toa); só render-tests pagam o custo do jsdom.
- **`@testing-library/jest-dom` importado no arquivo de render, não em setupFile global:** um setup global rodaria nos testes node também, onde jest-dom não faz sentido.
- **DESVIO DO PLANO - `vite.config.ts` mudou:** o plano dizia "sem mudança". Necessário porque `NODE_ENV=production` deste ambiente fazia o Vite carregar o React de produção nos testes (`React.act` ausente → testing-library v16 quebra). A guarda `if (process.env.VITEST)` força modo de teste **apenas** sob vitest; `vite build` não tem `VITEST` setado, então a produção fica intacta (confirmado: bundle 194 kB inalterado). É ajuste mecânico de infra, não mudança de escopo.
- **Piloto mínimo (renderiza filho / captura erro), sem testar reload/reset:** a lógica de reset já é coberta em `ErrorBoundary.test.ts` (node); o render-test prova só que o boundary captura e mostra o fallback.

## O Que NÃO Foi Feito (e Por Quê)

- **Sem setup global / sem mudar `environment` default:** opt-in por-arquivo é suficiente e mais seguro.
- **Não converti outros componentes para render-test:** escopo é só validar a infra com um piloto. Outros viram testes conforme necessidade.
- **Não testei o clique em "Resetar dados" (reload/limpar):** exigiria mockar `window.location.reload`; a lógica já está coberta em node. Pode entrar quando houver caso real que justifique.

## Aprendizados Para o Projeto

- **`NODE_ENV=production` neste ambiente afeta os testes, não só o `npm install`.** Já tínhamos a poda de devDeps (CHORE-011); agora apareceu na resolução do build do React. A guarda `if (process.env.VITEST)` no `vite.config` é o ponto certo para neutralizar isso sem afetar `vite build`.
- **testing-library v16 + React 19 exige o build de desenvolvimento do React** (`React.act` só existe nele). Sintoma: `React.act is not a function`.
- **Ambiente de teste por-arquivo (docblock) é a forma de baixo atrito** para introduzir jsdom num projeto majoritariamente node, sem penalizar a suíte existente.
