## Contexto

Na tela Detalhamento, com modo Autorizada ativo, o card "Manutenção" exibia uma única linha "Revisão Geral (autorizada)" agregando o pacote Honda + serviços avulsos trazidos pela TASK-RF-6.22 (kit transmissão, pneus e sapatas). Isso tornava a composição opaca: o usuário não conseguia saber se esses avulsos estavam calculados nem editar/desativar item específico.

O usuário confirmou durante a execução que o modo Independente estava correto do ponto de vista de UX e deveria servir como referência visual. A correção deveria afetar somente o modo Autorizada:

- "Revisão Geral (autorizada)" continua representando o pacote fechado Honda.
- Itens internos das revisões Honda não precisam aparecer no Detalhamento.
- Serviços fora do pacote Honda (`!incluidoNaRevisaoAutorizada`) precisam aparecer separados em Manutenção.
- O lápis dos avulsos autorizados deve abrir popup na própria tela, sincronizado com a página Mão de Obra.

## Planejamento Aprovado

**O que muda:**

- [src/utils/calculos.ts](../../../src/utils/calculos.ts): apenas no modo `autorizadas`, `base` passa a representar só o pacote Honda e `detalhes.servicos` recebe os avulsos com `ativo && !ehExcepcional && !incluidoNaRevisaoAutorizada && precoTotalAutorizada > 0`. O `total` continua igual: `base + soma dos avulsos`.
- [src/components/detalhamento/SecaoManutencao.tsx](../../../src/components/detalhamento/SecaoManutencao.tsx): trocar edição de serviço por `servicoId`, não por índice de revisão Honda.
- [src/pages/PaginaDetalhamento.tsx](../../../src/pages/PaginaDetalhamento.tsx): para avulsos autorizados, abrir popup de edição em vez de redirecionar para Mão de Obra. A linha "Revisão Geral" continua redirecionando para a aba Honda.
- [src/components/detalhamento/DialogEdicaoCusto.tsx](../../../src/components/detalhamento/DialogEdicaoCusto.tsx): adicionar alvo de edição para serviço autorizado e renderizar `CardServico` com `modo="autorizada"`.
- [src/utils/calculos.test.ts](../../../src/utils/calculos.test.ts): adicionar regressões para total inalterado e modo independente sem alteração.

**Critérios de aceite:**

- No autorizado, Manutenção mostra "Revisão Geral" + linhas separadas para serviços avulsos Honda.
- Cada avulso tem toggle individual, valor próprio e lápis funcional.
- O lápis do avulso abre popup editável no Detalhamento.
- Totais não mudam, só deixam de ficar escondidos numa linha agregada.
- Independente permanece sem alteração de comportamento.
- Testes e lint verdes; checagem TypeScript registrada.

## Decisões Tomadas

- **Não alterar modo Independente:** o print do independente era referência visual, não evidência de bug. O comportamento agregado da M.O. independente foi preservado.
- **Popup em vez de navegação para avulsos autorizados:** o usuário pediu edição na própria tela de Detalhamento. O popup reaproveita `CardServico`, mantendo o mesmo método já usado pelos outros popups sincronizados via reducer.
- **`precoMaoDeObra` em `CustoServicoRevisao` recebe `precoTotalAutorizada`:** o tipo já existia com esse nome legado, mas no modo autorizado o valor semântico é preço total Honda (peça + M.O.), conforme ADR-007.

## O Que NÃO Foi Feito

- **Persistência dos toggles finos de Manutenção:** durante a validação, o usuário encontrou que toggles de peças/serviços voltam a ligar ao sair da tela. Isso não foi corrigido nesta task porque exige mudança de modelo/persistência. Registrado como TASK-BG-014.
- **Renomear visualmente "Revisão Geral" para "Revisão Honda":** não foi necessário para cumprir o bug; manter o label evita mudança de texto fora do pedido.
- **Validação visual local via Vite:** o ambiente WSL/Node impediu subir o dev server; a validação visual foi feita pelo usuário no próprio app.

## Revisão

### Modo

Auto-revisão IA + validação visual humana.

### ✅ Bom

- Separação de cálculo ficou localizada em `calcularDetalhesRevisaoAnual`, sem alterar a mecânica de exclusão de peças da ADR-007.
- Popup usa o mesmo `CardServico` da página Mão de Obra, evitando duplicação de formulário e mantendo sincronização pelo `SET_SERVICO_INDEPENDENTE`.
- Teste novo protege a regra central: avulsos autorizados aparecem em `detalhes.servicos` sem alterar `revisao.total`.
- Teste novo protege a decisão de produto: modo independente continua agregado como antes.

### 🔴 Bloqueante

- Nenhum bloqueante encontrado após testes/lint e validação visual humana.

### 🟡 Importante

**Toggles finos de Manutenção não persistem**
- Onde: `src/pages/PaginaDetalhamento.tsx` (`manutencaoPorPeca`, `revisaoPorServico`, `revisao` em `useState` local) e `src/types/perfil.ts` (`configuracaoDisplay` sem campos persistidos para filtros finos).
- Problema: desativar item de Manutenção não sobrevive à navegação/retorno; o cálculo volta a incluir o item.
- Tarefa gerada: TASK-BG-014.

**Checagem TypeScript não executada**
- Onde: ambiente local WSL/Node.
- Problema: `npx tsc --noEmit` e alternativas falharam antes da análise TypeScript.
- Ação: registrado em Testes; `npm run test` e `npm run lint` passaram. Reexecutar `tsc` quando o ambiente Node/WSL estiver funcional.

### 🟢 Sugestão

- Considerar, em tarefa futura de UX, separar visualmente "Pacote Honda" e "Avulsos Honda" dentro da seção Manutenção se a lista crescer.

## Aprendizados Para o Projeto

- Quando o Detalhamento exibe custo composto por serviços, a UI precisa deixar claro quais itens vêm de pacote fechado e quais são avulsos editáveis.
- Reaproveitar `CardServico` nos popups preserva a sincronização com Mão de Obra sem criar segunda fonte de verdade.
- Filtros finos que afetam cálculo devem ser persistidos no perfil; estado local só serve para interação temporária sem impacto fora da tela.
