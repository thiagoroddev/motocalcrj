## Decisões Tomadas

- **`src/assets/icons/` em vez de `public/icons/`:** os SVGs são referência para os paths inlined nos componentes React não são servidos como URLs. `src/assets/` é o local correto para assets importados/referenciados pelo código-fonte. `public/` seria para assets acessados via URL direta.
- **Paths inlined nos componentes React (sem SVGR):** zero dependências novas. Os componentes encapsulam o `<path>` diretamente, o que garante `fill="currentColor"` e permite usar classes Tailwind `text-*` para cor. Alternativa (vite-plugin-svgr) adicionaria dependência apenas para economizar copy-paste dos paths.
- **`viewBox="0 -960 960 960"` preservado:** formato Material Symbols diferente do Material Icons clássico (`0 0 24 24`). Alterar o viewBox distorceria os ícones.
- **`IconMoeda` como texto:** não há ícone de Real (BRL) no Material Symbols. Texto `R$` estilizado via `className` é mais preciso semanticamente do que um ícone de outra moeda. Consistência com a identidade do produto (app brasileiro).
- **`aria-hidden="true"` em todos:** ícones são decorativos o conteúdo textual adjacente já descreve o dado. Screen readers não devem ler o ícone.

## Aprendizados para o Projeto

- Material Symbols usa `viewBox="0 -960 960 960"` diferente do Material Icons clássico e do lucide-react. Preservar o viewBox original ao inlinar os paths.
- `fill="#1f1f1f"` hardcoded nos SVGs baixados do Google Fonts sempre substituir por `fill="currentColor"` nos wrappers React para compatibilidade com Tailwind.
- `IconMoeda` como componente texto (`<span>R$</span>`) mantém a mesma interface de props que os ícones SVG, permitindo uso uniforme no JSX.
