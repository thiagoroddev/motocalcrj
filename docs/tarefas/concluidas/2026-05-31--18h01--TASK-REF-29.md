### 🔴 Bloqueante — ENCONTRADO E RESOLVIDO nesta task (Decisão C): a estimativa PADRÃO mudava silenciosamente
- Onde: `resolverIntervaloPeca` (`src/utils/calculos.ts`) + defaults `SERVICOS_INDEPENDENTES_PADRAO` (`src/context/perfilDefaults.ts`) vs `src/presets/pop110i.json`.
- Problema: como quase todos os serviços default são `ativo: true`, o serviço agora **sobrepõe** o intervalo do preset para o usuário default (`perfilUso: 'entrega'`). Mas os defaults do serviço **divergem** dos intervalos pesquisados do preset:
  - **óleo** (item de maior frequência): entrega era `intervaloKmEntrega 1250` → agora `troca-oleo 3000` ⇒ CPK do óleo cai ~58%.
  - vela 12000→6000 (CPK dobra); filtro de ar 12000→6000 (dobra); sapatas 12000→20000 (cai ~40%); kit relação 18000→12000; pneu traseiro 16000→15000.
  - Também **colapsa a distinção entrega/passageiro** (o serviço não tem variante por tipo de uso) e **ignora os `intervaloKmEntrega`** com notas de telemetria recentes ("motoboy troca 1000–1500 km").
- Evidência: o baseline `pneu_traseiro.proximaTrocaKm` foi alterado de `26000` para `25000` no teste (resultados existentes mudaram), e **não há teste fixando o CPK default do óleo** — a mudança maior passou sem cobertura; os testes novos só exercitam o comportamento novo.
- **Solução aplicada (Decisão C, escolhida pelo humano):** o serviço só sobrepõe o intervalo do preset **quando o usuário editou** (intervalo ≠ default em `SERVICOS_INDEPENDENTES_PADRAO`); sem edição, o preset (entrega/passageiro) segue canônico. Implementado em `resolverServicoComIntervaloEditado`, consumido por `resolverIntervaloPeca`, `PaginaInsumos` e `DialogEdicaoCusto`. Entrega o objetivo da DT-15 (edição reflete) **sem** mudar a estimativa default nem descartar os intervalos pesquisados. Testes da REF-29 corrigidos (óleo: serviço editado 2000; baseline `pneu_traseiro` de volta a 26000) + guard "serviço no default não sobrepõe → preset 1250"; INV-VIDA-UTIL-1 reescrita.
