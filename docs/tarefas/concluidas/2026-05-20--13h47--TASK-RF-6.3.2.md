## Decisões Tomadas

- **`migrarPerfil` usa `as any` pontual:** A função recebe dados de versões antigas do localStorage que não têm os novos campos. Usar `as any` no início e `as PerfilUsuario` no retorno é o mesmo padrão da migração v5→v6 anterior — aceitável porque é código de migração de dados, não lógica de negócio.
- **`oleo` herda `kmUltimaRevisao` na migração:** Usuários que já informaram o km da última revisão ganham o valor de óleo pré-populado, que é o componente com menor intervalo e mais relevante. Os demais ficam em 0 (= nunca trocado registrado).
- **`perfilPadrao.oleo = 0`:** No padrão, `kmUltimaRevisao` também é null; herdar null não faria sentido, então 0 é o default correto para novos usuários.
- **Sem `MARCAR_TROCAS_REVISAO` para motor:** O motor refeito usa `SET_MOTOR_REFEITO` separado porque é um campo `number | null`, não faz parte de `KmUltimaTrocas`. No onboarding, se o checkbox "fazer motor" estiver marcado, o passo despachará `SET_MOTOR_REFEITO` além de `MARCAR_TROCAS_REVISAO`.

## Aprendizados Para o Projeto

- Ao encadear migrações de schema, trocar `if >= N return` por `if < N { ... } if === N { ... }` permite adicionar versões sem reescrever a lógica anterior.
- `Object.fromEntries(array.map(c => [c, valor]))` é o idioma correto para merge parcial de objetos com chaves dinâmicas no TypeScript sem usar `reduce`.
