## Decisões Tomadas
- **Manter `fipeCache` (Opção A da ADR-015), não removê-lo:** o cálculo de IPVA lê `perfil.fipeCache?.valor` em `src/utils/calculos.ts` (gated). Trocar só a *fonte* do valor (tabelaFipe em vez de API) mantém o arquivo gated e o schema intactos. Remover `fipeCache` (Opção B) ficou registrado na ADR como alternativa para o futuro.
- **`SET_FIPE_CACHE` no avançar, sem `useEffect`:** o valor é derivado síncrono na render; gravá-lo em `salvarEAvancar` evita o `useEffect`/`useRef` antigos (anti-padrão "useEffect para derivar/sincronizar"). `fipeCache` só é gravado quando o ano existe na tabela — não polui o perfil com lixo.
- **Não reescrever o monólito `Requisitos_..._v6.md`:** é um snapshot versionado (ponto no tempo). A verdade ativa (`funcionais.md`, `nao-funcionais.md`, glossário, modelagem) foi atualizada.

## Aprendizados Para o Projeto
- Quando um valor já tem um **fallback hardcoded validado por schema**, "promover o fallback a fonte única" costuma ser uma simplificação de baixo risco — remove uma fronteira externa e uma máquina de estados inteira.
- Trocar a *fonte* de um dado sem mudar **onde ele é lido** (`perfil.fipeCache.valor`) mantém arquivos gated e schemas fora do diff — escopo menor, revisão mais barata.
