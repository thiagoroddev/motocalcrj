## Reformulação de escopo

Versão original em `pendentes.md` previa "direcionar para a tela de edição correspondente". Após discussão com o usuário em 24/05/26, definido modelo híbrido:

- **Popup com cards reaproveitados** das próprias páginas (sincronizado via `dispatch` → re-render automático em popup + página de origem).
- **Direcionamento** só para Revisão Geral Autorizada (que tem N cards e não cabe em popup).
- **Sem lápis** em Documentos (não editável — depende do modelo da moto).
- **Imprevistos** mantém edição inline atual (`SecaoImprevistos`), não tocada.

## Decisões tomadas

- **Manutenção/peça → 1 lápis só, popup com 2 cards (peça + MO).** Terceira via proposta pelo usuário no questionário, escolhida sobre "2 lápis separados" ou "1 lápis com tabs". Vantagem: UI menos poluída, usuário vê preço + MO como conjunto, padroniza com o popup de Combustível (que também tem múltiplos cards).
- **Financiamento no popup só mostra os inputs da modalidade ativa.** Categoria nem aparece no Detalhamento se moto for "quitada"; logo no popup só faz sentido renderizar financiada (parcela+restantes) OU alugada (aluguel+periodicidade). Para mudar o tipo de aquisição, usuário vai a Ajustes.
- **`CardItemPreco` ganhou prop opcional `mostrarDicaAbaMO?: boolean` (default `true`).** Em `PaginaVidaUtil` mantém o rodapé "Alterar na aba M. Obra"; no popup do Detalhamento fica `false` porque o `CardServico` com o intervalo editável está logo abaixo, tornando a dica redundante e confusa.
- **Ícones canônicos por página no popup:** `Wrench` (lucide-react) para "Mão de obra" e `Package` para "Preço da peça". Aparecem como headers seccionais dentro do popup de peça, identificando de qual página o dado é editável.
- **Navegação para Revisão Autorizada via `location.state`:** `{ abaInicial: 'honda', destaqueIndex?: number }`. `PaginaMaoDeObra` ativa a aba e, se há `destaqueIndex`, scrolla para o card e aplica `ring-2 ring-primary` por 2s. `LinhaRevisaoHonda` virou `forwardRef` e ganhou prop opcional `destacado`.
- **`MAPA_PECA_PARA_SERVICO` formalizado em `calculos.ts`.** Hoje o `resolverIntervaloPeca` faz `servicosIndependentes.find((s) => s.id === pecaId)` mas os IDs nem batem (`oleo_motor` vs `troca-oleo`) — sempre cai no fallback do preset. O popup precisa achar o `ServicoIndependente` correto para a peça, e esse mapeamento explícito também documenta o pareamento. `sapata_freio_traseiro` fica fora (não tem serviço cadastrado) e o popup graciosa­mente mostra só o card de preço.
- **TASK-DOC-008 fica para depois.** Novos componentes vão para `src/components/custos-pecas/` (nome novo já antecipa o rename), mas página continua `PaginaVidaUtil` até DOC-008 rodar — naming temporariamente inconsistente foi aceito.
- **`flex-shrink-0` → `shrink-0` nos arquivos tocados.** O linter apontou nos arquivos que toquei e a contagem majoritária do projeto (29 vs 11) é `shrink-0`. Fix cosmético sem mudança de comportamento.
- **`calculos.ts` recebeu novo símbolo `MAPA_PECA_PARA_SERVICO` exportado** (perto do `MAPA_PECA_PARA_KM_ULTIMA_TROCA` análogo já existente).

## Aprendizados Para o Projeto

- Quando a UX exige "ver o mesmo dado em mais de uma tela", **extrair o card como componente reutilizável** com `dispatch` injetado é o caminho — sincronização sai de graça, sem precisar montar mecanismo de "save/discard" que duplicaria estado.
- Tipos discriminados em React (`{ tipo: 'A' } | { tipo: 'B', x: string } | ...`) são particularmente úteis para dialogs polimórficos: o discriminador determina o conteúdo, e o TS força exaustividade no switch.
- Quando dois IDs no domínio precisam ser pareados por convenção (ex: `oleo_motor` ↔ `troca-oleo`), **documentar o pareamento como mapa explícito + teste** é melhor que esperar match implícito por igualdade de string que está em vias de ficar latente (como tinha em `resolverIntervaloPeca` — bug não-disparado porque o fallback sempre cobre, mas frágil).
- O padrão "extrair botão de ação com `stopPropagation`" (`BotaoLapisEdicao` da SecaoImprevistos para reuso) é uma boa unidade pequena — clique em botão dentro de cabeçalho clicável é cenário recorrente.
- A regra "ícone canônico por página" (Wrench=MaoDeObra, Package=CustosPecas) é útil em qualquer lugar que precise referenciar uma página fora do menu principal — vale aplicar futuramente em tooltips/breadcrumbs.

### Aprendizado adicional

- O padrão "state local em PaginaDetalhamento espelha dispatch" (já existia em `toggleFiltro`) é o jeito coerente de tratar filtros que precisam **ao mesmo tempo** ser reativos no nível da tela (state local) E persistentes (perfil). Aplicado a `imprevistosSugeridos` agora.
