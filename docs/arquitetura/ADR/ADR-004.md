# ADR-004: Modelo de Eventos por Serviço para Cálculo de Mão de Obra

**Data:** 19/05/26
**Status:** Aceita
**Decisores:** Thiago (humano), IA (Claude)

---

## Contexto

Durante o planejamento de TASK-RF-6.1 (Aba Mão de Obra) e TASK-RF-6.2 (Aba Autonomia), a análise do calculador revelou quatro problemas estruturais que inviabilizam a implementação direta das abas:

**1. `servicosMaoDeObra` é campo orfão**
O perfil armazena cinco preços de MO (R$30 óleo, R$50 kit, etc.) mas nenhum deles é lido pelo calculador. O modo independente usa `(kmAnual / 6.000) × R$150` - uma "visita genérica" sem relação com os serviços reais. Os valores editáveis na aba seriam decoração.

**2. MO sem intervalo**
Os preços de MO não têm `intervalKm`, tornando impossível calcular quantas vezes cada serviço ocorre por ano. Não há como derivar `CPK = precoMO / intervalKm` com a estrutura atual.

**3. Bug no cálculo Honda - tempo em vez de km**
O calculador usa `custoCicloCompleto / 42 meses × 12` (tempo fixo). Para um entregador com 25.000 km/ano, o ciclo de 36.000 km completa em ~1,4 anos, não 3,5 - subestimando o custo anual em ~2,4×. Além disso, `revisaoAutorizadaOverrides` é armazenado no perfil mas nunca aplicado no calculador.

**4. Conflito de responsabilidade entre abas**
"Autonomia" exibia preço de peças e vida útil juntos. Com a introdução do intervalo por serviço, a vida útil passa a ser propriedade do evento (serviço), não da peça. Manter as duas abas com responsabilidade sobreposta cria ambiguidade: qual intervalo vence?

---

## Decisão

**Adotar modelo de Evento por Serviço para o cálculo de mão de obra independente.**

Cada evento de manutenção (troca de óleo, troca de pneu, etc.) tem um custo total composto por peça + mão de obra, e ocorre a cada `intervalKm`. O custo anual é:

```
CPK_evento = (precoPecas + precoMO) / intervalKm
custoAnual = Σ CPK_evento × kmAnual  (sobre todos os serviços ativos)
```

O `intervalKm` pertence ao **serviço** (Mão de Obra). O `precoPecas` pertence à **peça** (Preço Peças). Ambos usam o mesmo intervalo do serviço para o cálculo.

### Mudanças estruturais

**1. Substituir `ServicosMaoDeObra` por `servicosIndependentes: ServicoIndependente[]`**

```ts
interface ServicoIndependente {
  id: string;
  nome: string;
  precoMaoDeObra: number;
  intervalKm: number;
  ativo: boolean;
  ehExcepcional: boolean;
}
```

Serviços predefinidos e seus defaults (valores reais implementados em `SERVICOS_INDEPENDENTES_PADRAO` - ver nota abaixo):

| id | nome | precoMO | intervalKm | ativo | ehExcepcional |
|---|---|---|---|---|---|
| `troca-oleo` | Troca de óleo | R$ 25 | 3.000 km | true | false |
| `troca-kit-transmissao` | Troca kit transmissão | R$ 60 | 12.000 km | true | false |
| `troca-pneu-dianteiro` | Troca pneu dianteiro | R$ 30 | 25.000 km | true | false |
| `troca-pneu-traseiro` | Troca pneu traseiro | R$ 30 | 15.000 km | true | false |
| `revisao-geral` | Revisão geral (independente) | R$ 80 | 6.000 km | true | false |
| `troca-vela` | Troca de vela | R$ 15 | 6.000 km | true | false |
| `troca-filtro-ar` | Troca filtro de ar | R$ 15 | 6.000 km | true | false |
| `retifica-cabecote` | Retífica de cabeçote | R$ 800 | 80.000 km | false | true |
| `retifica-completa` | Retífica completa | R$ 1.500 | 120.000 km | false | true |

> Para serviços com `ehExcepcional: true`, `precoMaoDeObra` é nome legado do campo; na UI o valor representa o serviço completo (peças + mão de obra).
>
> **Nota de implementação (20/05/26 - TASK-REF-11):** Os valores acima divergem do rascunho de planejamento em três aspectos, todos deliberados:
> - **IDs com hífen** (`troca-oleo`) em vez de underscore (`troca_oleo`): convenção adotada para uniformidade com kebab-case dos demais IDs do sistema.
> - **Preços de campo RJ** em vez de estimativas: valores pesquisados em oficinas independentes RJ (R$25 óleo, R$30 pneus, R$60 kit). Os valores do rascunho (R$95, R$125, R$300) eram estimativas iniciais não validadas.
> - **Lista diferente:** `freios` e `retifica_cabecote` foram substituídos por `troca-vela` e `troca-filtro-ar` - serviços mais frequentes e relevantes para motoboy Pop 110i.
>
> **Efeito colateral identificado (DT-15, endereçado pela TASK-REF-29):** Os IDs dos serviços (`troca-oleo`) divergem dos IDs das peças no Preset JSON (`oleo_motor`). A implementação atual resolve esse vínculo por `MAPA_PECA_PARA_SERVICO` em `calculos.ts`; `resolverIntervaloPeca`, `PaginaInsumos` e `DialogEdicaoCusto` usam esse mapa para preservar `ServicoIndependente.intervalKm` como fonte canônica.
>
> **Atualização posterior (23/05/26 - TASK-RF-6.10 / ADR-006):** `fazer-motor` foi substituído por `retifica-cabecote` e `retifica-completa`.
>
> **Atualização posterior (23/05/26 - TASK-BG-005):** retíficas continuam configuradas na aba Excepcional, mas não entram automaticamente em Revisão/Manutenção. No Detalhamento, aparecem em Imprevistos como sugestões desligadas por padrão, com custo derivado do preço e intervalo configurados aqui.

Serviços com `ehExcepcional: true` ficam agrupados em seção separada na UI. Quando `kmAtual` atinge o menor `intervalKm` excepcional, a tela exibe aviso sugerindo revisão desses serviços.

**2. "Aba Autonomia" renomeada para "Preço Peças"**

- Exibe preços de peças (original/paralela), editáveis pelo usuário
- `intervalKm` (vida útil) exibido como somente leitura, vindo do `ServicoIndependente` correspondente por convenção de `id`
- Peças sem serviço correspondente (ex: `filtro_ar`, `sapata_freio_traseiro`) mantêm o intervalo do preset
- Combustível (preço/litro e km/l) permanece editável na mesma aba - não é peça, mas segue o mesmo padrão de "parâmetros editáveis de custo operacional"

**3. Calculador - modo independente atualizado**

```
// substitui a lógica atual de visita genérica
custoMOAnual = Σ (precoMO[i] / intervalKm[i]) × kmAnual  para cada servico ativo e não-excepcional
custoMOExcepcional = Σ (precoMO[i] / intervalKm[i]) × kmAnual  para cada servico ativo e excepcional
```

As peças continuam calculadas pelo fluxo `calcularCpkPorPeca`, mas agora usando `ServicoIndependente.intervalKm` como intervalo canônico (quando houver serviço mapeado), em vez do `vidaUtilKm` do preset.

**4. Calculador - modo Honda corrigido**

```ts
// ANTES (incorreto - tempo fixo, ignora km real do usuário):
custoAnual = custoCicloCompleto / 42 × 12

// DEPOIS (correto - proporcional ao km percorrido):
custoAnual = (custoCicloCompleto / 36000) × kmAnual
```

`custoCicloCompleto` passa a aplicar `revisaoAutorizadaOverrides` (corrigindo o bug de não-aplicação).

**5. Schema - bump `schemaVersion: 5 → 6`**

Migration automática no `PerfilProvider`: ao carregar preset com `schemaVersion < 6`, os campos `servicosMaoDeObra.*` (valores legados) são descartados e `servicosIndependentes` é inicializado com os defaults da versão 6. Os preços legados não migram - os defaults do domínio são mais precisos.

**Escopo explicitamente fora desta ADR:**
A customização de quais peças compõem a "revisão geral" (usuário adiciona vela, filtro, etc.) é funcionalidade da tela Estimativa/Detalhamento, a ser especificada em task futura. Para esta ADR, "revisão geral" tem custo de MO = R$150 e `precoPecas = 0` no calculador.

## Consequências

### Positivas

- Cálculo independente reflete eventos reais (não média genérica): entregador com 25.000 km/ano vê custo real por tipo de serviço
- Honda corrigido: subestimativa de ~2,4× eliminada para usuários de alta rodagem
- Separação limpa de responsabilidades: Mão de Obra = dono do intervalo + MO; Preço Peças = dono do preço
- Extensível: novos serviços são linhas no array, sem mudança de schema
- Excepcional visível e acionável: usuário com moto velha pode ativar "fazer motor" ao invés de ignorar o custo

### Trade-offs Aceitos

- **Migration descarta valores legados de `servicosMaoDeObra`**: os preços legados (R$30, R$50, etc.) são substituídos pelos defaults do domínio (R$95, R$125, etc.). Aceitável - os defaults novos são baseados em pesquisa de campo e mais precisos que os valores originais.
- **Mapeamento serviço↔peça é por convenção de `id`**: não há campo `partId` explícito no schema. O calculador liga `ServicoIndependente.id === 'pneu_traseiro'` ao `PneuPreset.id === 'pneu_traseiro'` por convenção. Custo: implícito, mas controlado (IDs são constantes do domínio).
- **Custo Honda mudará para usuários existentes**: a correção do cálculo km-based aumenta o custo projetado para entregadores intensivos. É uma correção de bug, não mudança de comportamento intencional.

## Alternativas Descartadas

### Alternativa A: Manter objeto flat + campo paralelo `servicosMaoDeObraIntervalos`

Adicionar `Record<string, number>` de intervalos ao lado do objeto atual.

**Por que descartada:**
- Dois objetos sincronizados manualmente = fonte de inconsistência
- Não resolve extensibilidade (serviços fixos hardcoded no tipo)
- Não resolve custos excepcionais
- Ainda não resolve o bug Honda

### Alternativa B: Bundle peça + MO em `ServicoIndependente` (sem separação de abas)

Cada serviço carrega `precoMO` + `precoPecas` juntos, sem aba separada de preços.

**Por que descartada:**
- A escolha original/paralela é decisão de compra (não de serviço): o usuário decide onde compra a peça, independentemente de onde instala
- A mesma peça pode aparecer em múltiplos serviços (ex: vela em revisão geral e revisão Honda)
- Perde a capacidade de atualizar preços de peças globalmente sem tocar cada serviço

### Alternativa C: Manter cálculo Honda por tempo e não corrigir overrides

Simplificação que evita mudança no calculador.

**Por que descartada:**
- Subestimativa de ~2,4× para entregadores com 25.000 km/ano invalida o propósito central do app
- `revisaoAutorizadaOverrides` existe no schema para ser usado - mantê-lo ignorado é defeito, não feature
