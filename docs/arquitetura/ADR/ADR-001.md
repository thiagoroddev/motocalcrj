# ADR-001: Política de versões estáveis recentes e migração de ambiente frontend

- **Status:** Aceita
- **Data:** 16/05/26
- **Contexto:** Análise pós-TASK-REF-03
- **Decisores:** Humano + IA

---

## Contexto

Ao iniciar o projeto, nenhuma versão de dependência foi fixada. O tooling de scaffolding (Vite, shadcn CLI) escolheu versões seguras para ele, não necessariamente as mais recentes. O resultado foi:

- Tailwind CSS v3 (v4 disponível desde jan/2025 com reescrita completa);
- Vite v5 (v6 disponível), TypeScript 5.6 (5.8 disponível), Vitest v2;
- ESLint v8 com `.eslintrc.cjs` enquanto o ESLint global da máquina já é v10 (flat config);
- `omit=dev` no npm global causou três bloqueios operacionais durante TASK-REF-03.

A ausência de uma política explícita expõe o projeto a conflito contínuo com o ambiente local e a acúmulo silencioso de defasagem tecnológica.

---

## Decisão

### 1. Versões preferidas

Adotar sempre a **versão estável mais recente que exista contexto operacional de IA para suportar**. O critério não é "versão mais nova que existe" mas "versão mais nova que a IA consegue operar sem lacunas de contexto".

Em 16/05/26, isso significa:

| Pacote | Versão adotada | Justificativa |
|---|---|---|
| `tailwindcss` | v4 | Lançada jan/2025; IA tem contexto completo; reescrita mais limpa |
| `vite` | v6 | Lançada nov/2024; migração suave a partir do v5 |
| `typescript` | 5.8 | Lançada 2025; totalmente retrocompatível |
| `vitest` | v3 | Lançada 2025; API estável |
| `eslint` | v9 | Lançada 2024; flat config resolve conflito com global |
| `react` + `react-dom` | v19 | Lançada dez/2024; avaliar após Tailwind v4 estabilizar |
| `react-router-dom` | v7 | Lançada nov/2024; avaliar junto com React 19 |

### 2. Configuração npm de projeto

Criar `.npmrc` na raiz do projeto com `omit=` (vazio) para sobrescrever o `omit=dev` global da máquina. Isso garante que `npm install` sempre instale devDependencies neste projeto sem precisar de flag explícita.

### 3. Ordem de migração

Executar na seguinte ordem para minimizar conflito entre migrações:

1. **TASK-CHORE-004** - `.npmrc` (pré-requisito operacional para as demais)
2. **TASK-CHORE-005** - Vite, TypeScript, Vitest (bumps de baixo risco, sem breaking changes relevantes)
3. **TASK-RNF-006** - Tailwind v4 + shadcn/ui (janela ideal: agora, antes de mais componentes customizados)
4. **TASK-CHORE-007** - ESLint v9 flat config (resolve conflito com global; independente do Tailwind)
5. **TASK-RNF-008** - React 19 + React Router v7 (após stack base estabilizada)

### 4. Tailwind v4 e shadcn/ui

A migração para Tailwind v4 implica:

- Remover `tailwind.config.cjs`, `postcss.config.cjs` e `autoprefixer`;
- Instalar `tailwindcss@^4` e `@tailwindcss/vite` (plugin Vite direto, sem PostCSS);
- Mover configuração de tema de JS para CSS via bloco `@theme {}` em `index.css`;
- Substituir `@tailwind base/components/utilities` por `@import "tailwindcss"`;
- Substituir `darkMode: ['class']` por `@custom-variant dark (&:where(.dark, .dark *))` no CSS;
- Atualizar `components.json` do shadcn para `"tailwind": {"version": "4"}`;
- Regenerar os 12 componentes shadcn via `npx shadcn@latest add`.

Os tokens de cor no formato RGB (`--background: 13 19 33`) migram para `@theme {}` como `--color-background: rgb(13 19 33)`. Os class names existentes (`bg-background`, `text-foreground`, etc.) **não mudam**.

### 5. ESLint v9

A migração implica:

- Remover `.eslintrc.cjs`;
- Criar `eslint.config.js` (flat config);
- Atualizar `@typescript-eslint/eslint-plugin` e `@typescript-eslint/parser` para versões compatíveis com ESLint v9;
- Atualizar demais plugins ESLint para versões com suporte a flat config.

---

## Alternativas consideradas

**Manter versões atuais:** descartado. O conflito ESLint global/local já causou bloqueio operacional. Tailwind v3 com shadcn acumula configuração redundante que v4 elimina. A defasagem cresce a cada tarefa nova.

**Migrar tudo de uma vez:** descartado. O risco de conflito entre múltiplas migrações simultâneas supera o ganho de velocidade. A ordem sequencial definida isola falhas.

---

## Consequências

- Stack alinhada com o que modelos de IA conhecem bem em 2025;
- Eliminação do conflito ESLint global/local;
- Remoção de ~3 arquivos de configuração (tailwind.config, postcss.config, autoprefixer);
- shadcn/ui precisa ter os 12 componentes regenerados após Tailwind v4;
- TASK-REF-01 e TASK-REF-02 devem ser executadas **após** TASK-RNF-006 para não precisar de retrabalho de class names.
