## Achados

### REV-002-A01 - Monólito de requisitos v6 contradiz ADR-015/016 (FIPE/Revisão)
- **Severidade:** 🟡 Importante
- **Área:** docs/requisitos
- **Evidência:** `docs/requisitos/Requisitos_MotoCalc_RJ_v6.md` linhas 330 (`RF-ON-07: Chamar BrasilAPI FIPE no passo P3`), 880 (`FIPE | Automático via BrasilAPI (runtime)`), 918 (`API FIPE | BrasilAPI`), 1254/1306 (fluxo BrasilAPI). O cabeçalho diz "Supersede: todas as versões anteriores" mas o próprio doc ficou defasado: a BrasilAPI runtime foi aposentada (ADR-015) e o modelo de custo da revisão mudou (ADR-016).
- **Problema:** quem usar o v6 como "a" especificação reconstrói o fluxo FIPE errado (runtime), contradizendo o código atual. Os requisitos **ativos** (`funcionais.md`/`nao-funcionais.md`) já foram corrigidos, mas o v6 segue sendo referência grande e enganosa.
- **Recomendação:** após decisão do humano em 05/06/26, não manter o monólito por meio de novas notas. Migrar sua visão de produto e priorização ainda úteis para `docs/contexto-projeto-ai.md`, repontar documentos operacionais para suas fontes reais e remover o v6. O histórico continuará preservado pelo Git.
- **Tarefa(s) gerada(s):** TASK-DOC-015: migrar contexto útil, eliminar referências operacionais e remover o monólito v6
- **ADR(s) gerada(s):** -
- **Requisito/DT gerado:** -
- **Status do achado:** Resolvido pela TASK-DOC-015

### REV-002-A02 - Nomes internos "Honda" em calculos.ts já são multi-marca
- **Severidade:** 🟢 Sugestão
- **Área:** código
- **Evidência:** `src/utils/calculos.ts` (15 ocorrências de `KM_CICLO_REVISAO_HONDA` / `quantidadeRevisoesCicloHonda` / `basePacoteHonda` / `INTERVALO_REVISAO_INDEPENDENTE_KM`). Após a BG-022/ADR-016, o ciclo passou a vir do preset (`kmCicloRevisao = max(intervaloKm)`), então esses nomes "Honda" agora valem para qualquer marca (Yamaha inclusive).
- **Problema:** nome contradiz o comportamento (risco de leitura errada futura: alguém assume que é só Honda). `KM_CICLO_REVISAO_HONDA` virou fallback genérico; `quantidadeRevisoesCicloHonda` é parâmetro por-preset.
- **Recomendação:** renomear para neutro (`KM_CICLO_REVISAO_PADRAO`, `quantidadeRevisoesCiclo`, `basePacoteConcessionaria`) ao próximo toque aprovado em `calculos.ts` (gated). Já anotado na revisão complementar da BG-022.
- **Tarefa(s) gerada(s):** TASK-REF-37: renomear internos "Honda" → neutros + wrapper morto em `calculos.ts` (gated)
- **ADR(s) gerada(s):** -
- **Requisito/DT gerado:** -
- **Status do achado:** Resolvido pela TASK-REF-37

### REV-002-A03 - `calcularCustoRevisaoAnual` sem consumidor em produção
- **Severidade:** 🟢 Sugestão
- **Área:** código
- **Evidência:** `src/utils/calculos.ts:637` (export); `rg calcularCustoRevisaoAnual src` → só `calculos.test.ts` usa. A produção usa `calcularDetalhesRevisaoAnual` (o richer). O wrapper ficou só como API de teste.
- **Problema:** API pública morta em produção; não recebeu a opção `kmCicloRevisao` (ADR-016), então diverge do caminho real — pode confundir quem testar por ele.
- **Recomendação:** remover o wrapper e migrar os testes para `calcularDetalhesRevisaoAnual`, **ou** documentá-lo explicitamente como helper de teste. Gated (`calculos.ts`).
- **Tarefa(s) gerada(s):** TASK-REF-37 (junto da A02, mesmo toque gated)
- **ADR(s) gerada(s):** -
- **Requisito/DT gerado:** -
- **Status do achado:** Resolvido pela TASK-REF-37

### REV-002-A05 - Acordeão de categoria: header clicável é `<div>` sem teclado (a11y)
- **Severidade:** 🟢 Sugestão
- **Área:** UX/acessibilidade
- **Evidência:** `src/components/detalhamento/CategoriaAccordion.tsx:37-39` (`<div onClick={onToggleExpandido}>`, sem `role`/`tabIndex`/`onKeyDown`). Grep por `role=|onKeyDown|tabIndex` no arquivo → nenhum.
- **Problema:** expandir/recolher categoria só funciona com mouse/touch; teclado e leitores de tela não alcançam o controle. Os botões de ação (olho, lápis) têm `aria-label`, mas o header não.
- **Recomendação:** `role="button"` + `tabIndex={0}` + `onKeyDown` (Enter/Espaço), ou trocar o header por `<button>`. Prioridade baixa (app mobile-first), mas é gap real.
- **Tarefa(s) gerada(s):** TASK-CHORE-018: a11y do header do `CategoriaAccordion`
- **ADR(s) gerada(s):** -
- **Requisito/DT gerado:** -
- **Status do achado:** Resolvido pela TASK-CHORE-018

### REV-002-A06 - Bundle único > 500 kB (sem code-splitting)
- **Severidade:** 🟢 Sugestão
- **Área:** performance
- **Evidência:** `npm run build` → "Some chunks are larger than 500 kB after minification". App num único chunk (sem `lazy`/`Suspense` por rota).
- **Problema:** primeira carga maior que o ideal para um público mobile/3G (motoboys). Pré-lançamento, aceitável.
- **Recomendação:** code-split por rota (onboarding e abas) com `React.lazy` quando entrar a frente de PWA (RNF-PWA-*). Combinar com a TASK-RNF-8.2 (PWA completo).
- **Tarefa(s) gerada(s):** - (não criada; recomendada) dobrar na TASK-RNF-8.2 (PWA)
