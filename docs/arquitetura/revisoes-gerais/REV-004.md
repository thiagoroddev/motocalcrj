**Data:** 15/06/26
**Status:** Concluída
**Revisores:** Thiago (humano, solicitante), IA (Claude, tech lead)

## Contexto

A REV-003 (08/06/26) auditou o projeto após o épico do onboarding (RF-6.31) e o encerrou saudável.
Desde então o projeto passou por um **sprint de lançamento** (15/06): refinamentos do BG-037
(clamp de km + tabela "Faltam"), **limitação de largura para web** (coluna central), **PWA**
(`vite-plugin-pwa` + manifest + service worker), **limpeza da tela Perfil** (remoção de
Idioma/Aparência, diálogo Privacidade e Termos), **avisos de origem dos dados** (TASK-RF-10),
**deploy na Vercel** (`vercel.json`, branch `motocalcrjv1`) e ajustes de meta/OG + Sheet.

O humano pediu uma auditoria de tech lead do estado atual após o lançamento.

## Objetivo

Responder se o projeto inteiro está coerente após o lançamento — código, docs, ADRs, requisitos,
tarefas e rastreabilidade — com atenção especial a se o **ciclo de tarefa** foi mantido durante o
sprint final.

## Cobertura

### Incluído
- Código de produção (`src/`), testes e build de produção (com artefatos PWA).
- Configuração de deploy (`vite.config.ts`, `vercel.json`, `index.html`, manifest).
- Documentação (README, contexto, requisitos, convenções), ADRs, dívida técnica.
- Tarefas pendentes/em-andamento/concluídas e rastreabilidade (git log vs índice vs arquivos).

### Limites Operacionais
- Sem E2E/visual automatizado; UI validada por leitura + render/smoke tests + validação visual do
  humano em uso real (largura, popups, onboarding) ao longo da sessão.
- Sem profiling de runtime/PWA em dispositivo; performance avaliada pelo aviso de bundle do build.
- O deploy publicado na Vercel foi confirmado pelo humano (app no ar em `motocalcrj.vercel.app`),
  não auditado em runtime por esta revisão.

## Metodologia
Varredura de anti-padrões + verificação dos gates (typecheck/lint/test/build) + reconciliação
git↔índice↔em-andamento + leitura dirigida dos arquivos do sprint de lançamento. Classificação pelo
módulo 21. Cada achado aponta evidência verificável.

## Avaliação Geral

**Código saudável e no ar; processo (rastreabilidade) é o ponto fraco.** Os gates passam (466 testes
+ build com PWA), não há anti-padrões críticos, `localStorage` segue isolado em services e a dívida
técnica está zerada. **Porém o ciclo de tarefa foi abandonado no sprint de lançamento**: várias
entregas de porte Standard foram commitadas com mensagens ad-hoc, sem arquivo em `concluidas/`, sem
entrada no índice, e com `em-andamento.md` sujo (RF-10 ainda "EM DESENVOLVIMENTO"). Como o próprio
diferencial declarado do projeto é "os docs provam o processo", essa lacuna pesa mais que o normal.

**Veredito: APROVADO COM RESSALVAS** (app válido e publicado; rastreabilidade do sprint final
requer reconciliação).

## Achados

### REV-004-A01 — Ciclo de tarefa abandonado no sprint de lançamento (rastreabilidade)

- **Severidade:** 🟡 Importante
- **Área:** docs / processo
- **Evidência:** `git log` mostra `0208dd3 TASK-BG-038 concluida`, `e7aefa2 TASK-RF-10 concluída`,
  `6e9682d largura de tela ajustada para web`, `6ee382e limpeza concluída`, e
  `d7f70f1/4525098/c93b06c/9e6615b/8932057` (fixes do deploy). **Nenhum** desses tem arquivo em
  [`docs/tarefas/concluidas/`](../../tarefas/concluidas/) — o último arquivo/entrada de índice é
  **TASK-BG-037** (10h11). Além disso, [`em-andamento.md`](../../tarefas/em-andamento.md) ainda
  contém a **TASK-RF-10 como "EM DESENVOLVIMENTO"** (29 linhas), apesar do commit "TASK-RF-10
  concluída". Largura, PWA, deploy, limpeza do Perfil e correção do Sheet não receberam ID de tarefa.
- **Problema:** o ciclo (mover p/ `concluidas/` + índice + limpar `em-andamento`) não foi cumprido;
  há um "concluída" no git que é falso no ledger. Quebra o argumento de processo do projeto e dificulta
  reconstruir o que foi feito.
- **Recomendação:** reconciliar — criar os arquivos `concluidas/` (ou ao menos entradas de índice) de
  **BG-038** (refinamentos pós-BG-037) e **RF-10** (avisos + tipo de combustível); registrar o trabalho
  de **lançamento** (largura + PWA + deploy + limpeza do Perfil + Sheet/OG) como uma tarefa própria;
  **mover RF-10 para fora de `em-andamento.md`**; atualizar o índice.
- **Tarefa(s) gerada(s):** TASK-DOC-017 (reconciliar ciclo + backlog do sprint de lançamento)
- **ADR(s) gerada(s):** -
- **Requisito/DT gerado:** -

  da A01.

### REV-004-A03 — Bundle único cresceu para ~919 kB (performance)

- **Severidade:** 🟡 Importante
- **Área:** performance / build
- **Evidência:** `npm run build` → `dist/assets/index-*.js` **918,94 kB** (gzip 226,13 kB) + aviso de
  chunk > 500 kB. Sem `manualChunks` nem `import()` por rota. Era 696 kB na REV-003 (~+32%), agora em
  produção real e com precache PWA de **2,58 MiB**.
- **Problema:** primeiro carregamento pesado para o público-alvo (motoboy em rede móvel), agravado por
  estar no ar e ser precacheado pelo service worker.
- **Recomendação:** lazy-load por rota (`React.lazy` + `Suspense`) e/ou `manualChunks` (vendors).
  Pertence ao escopo de performance já no backlog.
